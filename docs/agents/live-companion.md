# The real app against a live companion

Use this when a proof needs the real app talking to a real Squadd companion: pairing, presence, chat, links. It works from the Linux sandbox. #8, #11 and #33 each rebuilt it by hand; #33 marked the proof impossible and the PR judge said NO.

The sandbox runs a disposable server and companion, a public HTTPS tunnel exposes the companion, and a workflow on a `foto/<issue>-live` branch runs one test class on the maintainer's Mac runner against it.

1. **Disposable server and companion.** In your own worktree of `openmausbot` (`git worktree add --detach <dir> origin/dev`, then in it `pnpm install --frozen-lockfile --ignore-scripts`, about 2 s: a new worktree has no `node_modules`, and a link to another checkout's misses packages added on `dev` since, so the server stops with `ERR_MODULE_NOT_FOUND`), with `HOME` in your scratchpad and companion ports of your own (other sessions use 18899-18911, 19737, 20410-20411):
   `timeout 7200 node --experimental-strip-types scripts/control-omb.ts launch` starts the server with the fake Claude engine (`server/testing/fake-claude-cli.ts`), a temporary `HOME` and two free ports of its own, and prints a JSON with `url`: its port is the companion's `OMB_PORT`. Scripted replies: `FAKE_CLAUDE_REPLIES='["first","second"]'`; a turn that stays running until you release it: `FAKE_CLAUDE_MODE=hang FAKE_CLAUDE_RELEASE=<file>`. Don't start `node server/index.ts` with `FAKE_CLAUDE_MODE`: only the fake engine reads it, so the server runs the real Claude engine, answers «Not logged in» and #21 lost 4 minutes on it.
   `OMB_PORT=<port of url> OMB_COMPANION_PORT=<c> OMB_CONTROL_PORT=<c+1> OMB_CONTROL_TOKEN=<random> OMB_COMPANION_DIR=<dir> OMB_COMPANION_BONJOUR=0 timeout 7200 node companion/src/index.ts`
2. **Pair.** `POST :<c+1>/pairing` with header `x-openmausbot-control-token` gives a `code`; `POST :<c>/api/pair` with `{"code","deviceName"}` gives the device `token`.
3. **Tunnel: serveo.** `ssh -p 443 -o ConnectTimeout=15 -o ServerAliveInterval=20 -o ExitOnForwardFailure=yes -R 80:127.0.0.1:<c> serveo.net`, restarted in a loop. Port 443, because serveo's port 22 is not always reachable from the sandbox (closed on 20/11 while 443 answered); `ConnectTimeout` makes a blocked port fail in seconds instead of hanging silently. Its address (`https://….serveousercontent.com`) changes about every 12 minutes: the loop writes each new one into a secret gist of your own (`gh gist create`, then `gh api -X PATCH gists/<id> -f "files[current.txt][content]=$url"`), and a `curl` every 20 s keeps the tunnel busy. Don't use lhr.life (changes address, 502), cloudflared (holds back SSE) or bore (plain HTTP, refused by ATS).
4. **Secrets with your own names**, e.g. `SQUADD_PRESENCE_LOOKUP` = `https://api.github.com/gists/<id>` and `SQUADD_PRESENCE_TOKEN` = the device token (`gh secret set <NAME> --repo SQUADD26/squadd-multi-agents-ios < file`). Another session may be using `SQUADD_LIVE_*` at the same time (#8 overwrote #11's).
5. **Test and workflow.** The test runs only when its environment names the lookup and the token, and re-reads the gist on each try (16 tries every 15 s), as `liveAddress` in `SquaddChatLivePhotoTests` on `foto/11-chat-squadd-3`. Copy `live-companion/foto-live.yml` to `.github/workflows/foto-<issue>-live.yml` on a branch `foto/<issue>-live` that is never merged, set the names marked `CHANGE`, push. The push also starts PR iOS on that branch, which would hold the other Mac runner: a few seconds after it, cancel it by workflow file, never by name (names have spaces), `gh run list --branch foto/<issue>-live --workflow pr-ios.yml --json databaseId,status -q '.[]|select(.status!="completed")|.databaseId' | xargs -rn1 gh run cancel`. Push that branch **once per PR**, when the work is done and the PR iOS run is green, just before merging: the Mac runners are shared and a live run holds one for minutes, so test with the local tests and PR iOS until then. Keep the `push` trigger: sessions can't start a check with `gh workflow run` (the CI guard refuses it), so another live run is a new push, only after a fix. The companion's side of the record (for example `lastActiveAt` in `<HOME>/.openmausbot/brief.json`) is read in the sandbox while the run goes.
6. **Clean up** when the PR is merged: stop server, companion, tunnel loop and pinger; delete the gist, the secrets and the `foto/<issue>-live` branch.
